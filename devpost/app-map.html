Run Ledger

A map of the proof of concept, not the product. Open the product with runledger serve. This page is a snapshot and can drift from later edits.

What it is

Run Ledger prefixes a command, writes the ending into a SQLite file on this computer, and shows that file on a local page. An optional POST fires when the job finishes or crashes. Pieces:

  • CLI — src/runledger/cli.py reads the command after --.
  • Runner — src/runledger/runner.py starts the process, keeps the log tail, and asks the sampler.
  • Sampler — src/runledger/sampler.py reads nvidia-smi, or builds a labeled demo curve.
  • Store — src/runledger/db.py is the only SQL. One file, ~/.runledger/runs.sqlite.
  • Page — src/runledger/server.py plus src/runledger/dashboard.html.
  • Webhook — src/runledger/webhook.py, only if a URL is saved.

One action, through the code

You run runledger -- python -c "print('runledger-ok')" and the page shows that run. Reference route — follow it in the editor; it is not a claim that someone walked it live.

Stops

1. Where the command enters — src/runledger/cli.py

Search for if command in ("--", "run"). That branch passes the arguments after -- to runner.execute. serve is the other door, into server.serve.

2. Where the ending is written — src/runledger/runner.py

Search for def execute. It inserts a running row, streams stdout and stderr, samples at the start and again when the process exits, then calls webhook.maybe_notify. The return value is the child's exit code.

3. Where the page reads it — src/runledger/server.py and dashboard.html

Search server.py for /api/runs. The HTML file fetches that JSON and draws the list and the chart. Same SQLite file as the CLI. No network asset.

To change this, start here

  • Sample gap (default 3 seconds): cli.py interval or 3.0, and the wait inside runner.execute.
  • Empty-page sentence: dashboard.html, the string Nothing recorded yet.
  • Bot message text: webhook.py summary_lines.
  • Shape of the fake history curves: demo_data.py.

A practice to reuse

The product doc asked for a checkable result: a short command still produces a stored tail and at least one sample (devpost/prd.md, "Sample the GPU"). The runner therefore samples once up front and once at exit, because a python -c command can finish before a 3-second timer. tests/test_runner.py function test_short_command_records_tail_and_sample is the check. On the next project, write the done line as something you can see, then point one test at that line before adding a second feature.
